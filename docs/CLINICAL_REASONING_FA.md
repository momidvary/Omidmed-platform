# استدلال بالینی ساختاریافته و پیش‌نویس هوش مصنوعی

در صفحه **Case Analysis**، بعد از انتخاب کیس، بخش **«شرح حال و معاینه ساختاریافته»**
اضافه شده است. فیزیوتراپیست یافته‌ها را با چند کلیک ثبت می‌کند و برنامه
فرضیه‌های موقت را **با دلیل هر رتبه** مرتب می‌کند. اگر هوش مصنوعی فعال باشد،
همین یافته‌ها به پیش‌نویس هوش مصنوعی هم داده می‌شود.

> این خروجی **پشتیبانی نسبی از یافته‌های ثبت‌شده** است؛ نه احتمال است و نه تشخیص.
> تصمیم نهایی همیشه با معاینه و قضاوت فیزیوتراپیست است.

## نواحی پشتیبانی‌شده
گردن، شانه، کمر، لگن (هیپ)، زانو، مچ و پا. برای Post-op، نورولوژیک و ورزشی هنوز
ماژول ساختاریافته وجود ندارد و همان قالب قبلی نمایش داده می‌شود.

## روش کار
1. **چک‌لیست شرح حال:** برای هر سؤال «بله / خیر / پرسیده نشده» را بزنید.
   تحریک‌پذیری (SIN) را هم انتخاب کنید.
2. **تست‌های معاینه:** فقط تست‌هایی را که انجام داده‌اید «مثبت / منفی / نامشخص»
   کنید. زیر هر تست، حساسیت و ویژگی منتشرشده با منبع آن (در صورت وجود) آمده است.
3. **یادداشت‌های معاینه:** دامنه حرکتی، قدرت، غربالگری عصبی، لمس و … (اختیاری).
4. **فرضیه‌های موقت** (ستون کنار) همزمان به‌روز می‌شوند:
   - برچسب سطح پشتیبانی (قوی‌تر / نسبی / کم / خلاف آن)؛
   - دکمه **«چرا»**: هر یافته با وزن مثبت یا منفی‌اش؛
   - **آموزنده‌ترین تست‌های بعدی** برای جدا کردن فرضیه‌های اول؛
   - **قوانین غربالگری** هر ناحیه (اتاوا، کلاستر میلوپاتی، شریان گردنی و …)؛
   - هشدار قرمز اگر فرضیه‌ای جدی (مثل میلوپاتی، پارگی آشیل، شکستگی استرسی،
     کمردرد التهابی) از یافته‌ها پشتیبانی بگیرد → ارجاع پزشکی پیش از درمان.
5. **ذخیره یافته‌ها:** هر ذخیره یک نسخه جدید می‌سازد (نسخه قبلی پاک یا بازنویسی
   نمی‌شود). اگر همکار دیگری همزمان ذخیره کرده باشد، برنامه جلوی بازنویسی را
   می‌گیرد و می‌خواهد صفحه را تازه کنید.

رتبه‌بندی تا وقتی غربالگری ایمنی (Red Flag) کامل و پاک نباشد قفل است.

## چه کسی دسترسی دارد
فقط صاحب کلینیک و فیزیوتراپیستِ تخصیص‌یافته به بیمار. کارمند کلینیک، بیمار و
مدیر پلتفرم یافته‌ها را نمی‌بینند و نمی‌توانند ثبت کنند.

## نصب روی Supabase
فایل `database/supabase-sql-editor/upgrades/029_case_clinical_findings.sql` را
کامل در **SQL Editor** کپی و **Run** کنید. پیام موفقیت:
`029_case_clinical_findings.sql applied`.

## فعال کردن هوش مصنوعی (OpenAI)
بدون این مرحله، بخش ساختاریافته و رتبه‌بندی کامل کار می‌کند؛ فقط پیش‌نویس هوش
مصنوعی خاموش است.

**پیش از فعال‌سازی:** داده بالینی (بدون نام و شماره، ولی شامل شرح حال و یافته‌ها)
به OpenAI فرستاده می‌شود. این کار نیازمند رضایت/اطلاع‌رسانی به بیمار و تصمیم
مسئول حفاظت داده کلینیک است. OpenAI برای حساب‌ها و کارت‌های بانکی ایران خدمات
ارائه نمی‌دهد؛ حساب و پرداخت باید طبق قوانین و شرایط استفاده OpenAI باشد.

در Vercel، **Settings → Environment Variables**، این متغیرها را برای Production
اضافه و سپس **Redeploy** کنید:

| Key | Value |
|---|---|
| `NEXT_PUBLIC_ENABLE_CLINICAL_AI_DRAFTS` | `true` |
| `ENABLE_CLINICAL_AI_DRAFTS` | `true` |
| `OPENAI_CLINICAL_DATA_PROCESSING_APPROVED` | `true` (فقط پس از تصویب بالا) |
| `OPENAI_API_KEY` | کلید API از platform.openai.com (محرمانه؛ گزینه Sensitive) |
| `OPENAI_MODEL` | شناسه مدلی از OpenAI که Structured Outputs را پشتیبانی می‌کند (فهرست مدل‌ها در مستندات OpenAI) |

سقف استفاده پیش‌فرض: ۵ درخواست در دقیقه، ۴۰ در روز برای هر کاربر، ۵۰۰ در روز برای
کلینیک (با `CLINICAL_AI_*_LIMIT` قابل تغییر).

## استفاده از هوش مصنوعی
1. یافته‌ها را در Case Analysis **ذخیره** کنید.
2. دکمه **«درخواست تشخیص افتراقی رتبه‌بندی‌شده از هوش مصنوعی»** را بزنید
   (یا در **AI Assistant** همان کیس را انتخاب و پیشنهاد اول را بزنید).
3. مدل شرح حال کیس، یافته‌های ذخیره‌شده با دقت تست‌ها و رتبه‌بندی قاعده‌محور را
   دریافت می‌کند و باید آن را **نقد** کند (موافقت/مخالفت با دلیل)، فرضیه‌ها را از
   بیشتر به کمتر حمایت‌شده مرتب کند و تست‌های جداکننده را نام ببرد.
4. پیش‌نویس فقط پس از **Accept / Edit / Reject** شما اثر دارد؛ هر درخواست و
   پاسخ در لاگ ممیزی ثبت می‌شود و شماره تلفن/ایمیل داخل یادداشت‌ها حذف می‌شود.

اگر مدل خطا بدهد، رد کند یا زمانش تمام شود، هیچ پاسخ جایگزینی ساخته نمی‌شود.

## محتوای بالینی و بازبینی آن
سؤال‌ها، تست‌ها، وزن‌ها و منابع در `apps/web/lib/clinical/reasoning/knowledge.ts`
است. وزن‌ها دستی و قابل مشاهده‌اند (±۱ ضعیف، ±۲ متوسط، ±۳ قوی) و ارقام دقت فقط
برای تست‌هایی آمده که منبع رایج دارند. **پیش از استفاده بالینی، یک فیزیوتراپیست
ارشد محتوا را با منابع روز بازبینی کند.** هر تغییر محتوا باید `KNOWLEDGE_VERSION`
را بالا ببرد تا نسخه ذخیره‌شده هر یافته مشخص باشد.
