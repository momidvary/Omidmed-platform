# مدیریت بیماران (راهنمای مبتدی)

## پیش‌نیاز: اجرای Migration ها
در Supabase → SQL Editor، به ترتیب و هرکدام جداگانه Run کنید:
`001 → 002 → 003 → 004 → 010 → 011 → 012 → 013 → 014`
(فایل‌ها در `database/migrations/`. داده دمو فقط `database/seed/seed.dev.sql`
و فقط روی پروژه تستی.)

## فهرست بیماران — `/patients`
- جستجو بر اساس نام یا شماره (ارقام فارسی هم پذیرفته می‌شود)
- فیلتر وضعیت، فیزیوتراپیست مسئول، و «فقط دوره فعال»
- ستون‌ها: وضعیت، دوره فعال، جلسات انجام‌شده/برنامه، آخرین جلسه
- دسکتاپ جدول، موبایل کارت

## ساخت بیمار — `/patients/new`
1. نام و نام خانوادگی (الزامی) و بقیه فیلدها را پر کنید.
2. شماره موبایل خودکار به فرمت استاندارد (+98…) تبدیل می‌شود؛ شماره
   نامعتبر همان‌جا رد می‌شود.
3. اگر شماره در همین کلینیک تکراری باشد، هشدار می‌گیرید و فقط با تأیید
   صریح («شماره مشترک خانواده») ساخته می‌شود — هیچ ادغام خودکاری نیست.
4. کلینیک از عضویت شما تعیین می‌شود، نه از فرم؛ RLS دوباره سمت سرور
   بررسی می‌کند.
5. اگر ذخیره شکست بخورد فرم پاک نمی‌شود.
6. حذف بیمار وجود ندارد — فقط «بایگانی» (Soft Delete).

## پرونده بیمار — `/patients/[id]`
تب‌ها: نمای کلی (دوره فعال + شمارش جلسات + خط زمانی)، دوره‌های درمان،
اطلاعات اداری. تب‌های نوبت/تیکت/تمرین/مدارک فعلاً Placeholder هستند.

## دسترسی‌ها (خلاصه)
- منشی: فقط اطلاعات اداری؛ نمی‌تواند ارزیابی/جلسه/اندازه‌گیری بسازد.
- فیزیوتراپیست: فقط بیماران کلینیک خودش را می‌بیند و فقط برای بیماران
  تخصیص‌یافته پرونده بالینی می‌نویسد.
- بیمار: به این صفحات دسترسی ندارد (پرتال خودش را دارد).
