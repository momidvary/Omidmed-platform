# ورود بیمار با شماره همراه و کد پیامکی (ملی‌پیامک)

بیمار در `/patient` فقط شماره همراه را وارد می‌کند، کد ۶ رقمی را پیامک دریافت
می‌کند و وارد پرتال می‌شود. ایمیل، رمز عبور و ثبت‌نام آزاد برای بیمار وجود ندارد:
کلینیک شماره را در پرونده ثبت و حساب پرتال را از پنل **Patients → Manage** وصل
می‌کند. شماره‌ای که در کلینیک ثبت نشده، کدی دریافت نمی‌کند (هزینه پیامک کنترل
می‌شود). ورود کادر درمان همچنان با ایمیل و رمز عبور است.

**امنیت:** کد ورود را فقط Supabase می‌سازد و بررسی می‌کند. برنامه فقط آن را از طریق
ملی‌پیامک تحویل می‌دهد؛ کد و کلید API هیچ‌جا لاگ یا ذخیره نمی‌شوند و هر درخواست
Supabase با امضای دیجیتال (Hook secret) بررسی می‌شود.

## پیش‌نیاز
نسخه جدید برنامه روی Vercel منتشر شده باشد (Supabase باید بتواند آدرس
`https://<دامنه-شما>/api/auth/sms-hook` را صدا بزند؛ آدرس localhost کار نمی‌کند).

## ۱) ملی‌پیامک: کلید API و الگوی کد
1. در پنل ملی‌پیامک از **توسعه دهندگان → تنظیمات وبسرویس** مقدار **APIKey** را
   با دکمه کپی بردارید (محرمانه است؛ در چت یا اسکرین‌شات نفرستید). این کلید به
   جای رمز پنل استفاده می‌شود، پس **نام کاربری پنل** را هم لازم دارید.
   در همان صفحه فهرست **IP مجاز** را خالی بگذارید (IP سرورهای Vercel ثابت نیست).
2. در بخش **ارسال با الگو (خدماتی)** یک الگو بسازید، مثلاً:
   `کد ورود شما به پرتال بیمار: {0}`
3. پس از تأیید الگو، **شناسه عددی الگو (bodyId)** را یادداشت کنید.

## ۲) Supabase: فعال کردن Hook ارسال پیامک
1. **Authentication → Hooks** → **Send SMS hook** → نوع **HTTPS**.
2. آدرس: `https://<دامنه-vercel-شما>/api/auth/sms-hook`
3. **Generate secret** را بزنید و مقدار (با `v1,whsec_` شروع می‌شود) را کپی کنید.
4. ذخیره و فعال کنید.

## ۳) Vercel: متغیرها
در **Settings → Environment Variables** اضافه کنید و بعد **Redeploy** بزنید:

| Key | Value |
|---|---|
| `SEND_SMS_HOOK_SECRET` | همان secret مرحله ۲ |
| `MELIPAYAMAK_API_KEY` | کلید API ملی‌پیامک |
| `MELIPAYAMAK_OTP_PATTERN` | شناسه عددی الگو (bodyId) |
| `MELIPAYAMAK_USERNAME` | نام کاربری پنل ملی‌پیامک (معمولاً شماره همراه حساب) |

اگر به‌جای APIKey پنل، توکن کنسول (console.melipayamak.com) دارید،
`MELIPAYAMAK_USERNAME` را تنظیم نکنید.

`SMS_PROVIDER` را در Vercel تنظیم نکنید (پیش‌فرض ملی‌پیامک است؛ مقدار `mock`
فقط برای توسعه محلی است و در production پذیرفته نمی‌شود).

## ۴) Supabase: فعال کردن ورود با تلفن
**Authentication → Sign In / Providers → Phone** را فعال کنید. با فعال بودن Hook
مرحله ۲، ارسال پیامک از طریق برنامه انجام می‌شود و تنظیم Twilio و مانند آن لازم
نیست.

## ۵) دیتابیس
فایل `database/supabase-sql-editor/upgrades/028_patient_phone_accounts.sql` را
کامل در SQL Editor کپی و Run کنید (پیام موفقیت: `028_patient_phone_accounts.sql applied`).

## ۶) تست
1. **Patients → Manage** بیمار → شماره همراه (از پرونده پر می‌شود) → تیک تأیید
   رضایت → **Link portal account**.
2. در `/patient` همان شماره را وارد کنید → **دریافت کد ورود** → کد پیامک‌شده را
   وارد کنید.

## عیب‌یابی
پیام‌هایی که بیمار می‌بیند:

| پیام | علت |
|---|---|
| «این شماره در کلینیک ثبت نشده است» | حساب این شماره به پرونده‌ای لینک نشده؛ مرحله ۶-۱ |
| «ورود با شماره همراه هنوز در سرور فعال نشده» | مرحله ۴ انجام نشده |
| «ارسال پیامک ورود در سرور هنوز کامل تنظیم نشده است» | Hook درست وصل نیست: آدرس Hook در Supabase، یا `SEND_SMS_HOOK_SECRET` / `MELIPAYAMAK_API_KEY` / `MELIPAYAMAK_OTP_PATTERN` در Vercel تنظیم نشده یا بعد از افزودن آن‌ها **Redeploy** نشده |
| «ارسال پیامک انجام نشد» | ملی‌پیامک ارسال را نپذیرفت (کلید، الگو یا اعتبار)؛ لاگ‌ها را ببینید |
| «تعداد درخواست‌ها زیاد بود» | محدودیت Supabase (Authentication → Rate Limits) |

لاگ‌ها: در Vercel → **Logs** خطوط `[sms-hook]` با برچسب علت؛ شماره‌ها ماسک‌شده‌اند:

| برچسب | معنی |
|---|---|
| `invalid signature` | `SEND_SMS_HOOK_SECRET` با secret مرحله ۲ یکی نیست |
| `SMS provider is not configured` | کلید یا شناسه الگو در Vercel تنظیم نشده |
| `invalid_api_key` | کلید API یا نام کاربری نادرست است؛ برای APIKey پنل، `MELIPAYAMAK_USERNAME` لازم است |
| `webservice_disabled` | دسترسی وب‌سرویس در پنل غیرفعال است؛ با پشتیبانی ملی‌پیامک تماس بگیرید |
| `invalid_pattern` | الگو تأیید نشده یا شناسه اشتباه است |
| `insufficient_credit` | اعتبار پنل کافی نیست |
| `network` | ارتباط با ملی‌پیامک برقرار نشد |
