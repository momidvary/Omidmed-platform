# ورود همه کاربران با شماره موبایل (Phone OTP)

با تنظیم `NEXT_PUBLIC_AUTH_MODE=phone_otp`، روش ورود برای هر پنج نقش
(platform_admin، clinic_owner، therapist، clinic_staff، patient) شماره
موبایل + کد یک‌بارمصرف پیامکی می‌شود. Magic Link و کد ملی وجود ندارند؛
کد ملی فقط یک فیلد اطلاعاتی اختیاری در پرونده است.

حالت پیش‌فرض `NEXT_PUBLIC_AUTH_MODE=email_password` است (ورود با
ایمیل/رمز؛ بدون نیاز به راه‌اندازی پیامک). **تغییر حالت ورود فقط روش
احراز هویت را عوض می‌کند** — نقش‌ها، بیماران، پرونده‌ها و RLS همیشه از
`auth.uid()` و جداول profiles / clinic_members / patient_users /
patient_therapists تعیین می‌شوند و با تغییر حالت هیچ تغییری نمی‌کنند.
اگر در حالت phone_otp سرویس پیامک هنوز تنظیم نشده باشد، برنامه crash
نمی‌کند و پیام «ارسال پیامک ناموفق بود» نمایش داده می‌شود.

## جریان ورود
1. کاربر کد کشور (پیش‌فرض ایران +۹۸) و شماره موبایل را وارد می‌کند
   (ارقام فارسی/عربی خودکار تبدیل می‌شوند؛ فرمت‌های 0912…، 912…،
   +98912…، 0098912… همه پذیرفته و به +98912… استاندارد می‌شوند).
2. در صورت فعال‌بودن CAPTCHA (Turnstile)، بررسی امنیتی انجام می‌شود.
3. «ارسال کد تأیید» → `signInWithOtp` با `shouldCreateUser: false` —
   یعنی هیچ شماره ناشناسی نمی‌تواند خودش حساب بسازد؛ حساب‌ها فقط توسط
   مدیر/کلینیک ساخته می‌شوند.
4. کد ۶ رقمی وارد می‌شود (شماره به‌صورت Mask شده نمایش داده می‌شود؛
   شمارش معکوس ۶۰ ثانیه‌ای برای ارسال مجدد؛ امکان اصلاح شماره).
5. بعد از `verifyOtp`، نقش کاربر از جدول `profiles` (نه از فرم!) خوانده
   و عضویتش در `clinic_members` یا `patient_users` بررسی می‌شود:
   - بیمار → `/patient`
   - نقش‌های کلینیکی → داشبورد فیزیوتراپیست
   - حساب بدون اتصال معتبر → خروج خودکار + پیام عمومی «حساب کاربری شما
     هنوز به یک کلینیک یا پرونده معتبر متصل نشده است…» (هیچ جزئیات
     دیتابیسی نمایش داده نمی‌شود).

## نشست (Session)
Session با `@supabase/ssr` حفظ می‌شود: رفرش صفحه باعث خروج نمی‌شود و
فقط در خروج دستی، انقضای نشست، یا دستگاه جدید دوباره OTP لازم است.
دکمه «خروج» در هر دو پنل موجود است.

## تنظیمات Rate Limit در Supabase
پنل → Authentication → Rate Limits:
- **SMS sent per hour**: پیشنهاد ۳۰ برای شروع (پیش‌فرض معمولاً کافی است)
- **OTP verification attempts**: محدودیت تلاش کد اشتباه توسط خود
  Supabase اعمال می‌شود.
- فاصله ارسال مجدد در UI: ۶۰ ثانیه؛ Supabase هم حداقل فاصله خودش را
  دارد (`sms_otp` throttle).
همچنین Authentication → Attack Protection → CAPTCHA را با کلید
Turnstile فعال کنید (راهنمای CAPTCHA در MELIPAYAMAK_SETUP_FA.md بخش آخر).

## سرویس ارسال پیامک
Provider پیش‌فرض **ملی‌پیامک** است — راه‌اندازی کامل (وب‌سرویس، کلید
API، الگوی خدماتی، secrets، deploy، تست واقعی و رفع خطا) در
`docs/MELIPAYAMAK_SETUP_FA.md`. کاوه‌نگار به‌عنوان جایگزین پشتیبانی
می‌شود (`docs/KAVENEGAR_SETUP_FA.md`). در هر دو حالت، کد OTP را فقط
Supabase تولید می‌کند و کلیدها فقط در Supabase Secrets هستند.

## چک‌لیست تست دستی (بعد از راه‌اندازی پیامک واقعی)
برای هر پنج نقش یک شماره واقعی آماده کنید و این‌ها را تیک بزنید:
- [ ] ورود هر ۵ نقش با OTP و هدایت به داشبورد درست
- [ ] شماره ثبت‌نشده → پیام عمومی (بدون افشای وجود/عدم وجود شماره)
- [ ] حساب بدون profile یا بدون عضویت → خروج + پیام عمومی
- [ ] کد اشتباه/منقضی → پیام درست، شماره پاک نمی‌شود
- [ ] ارسال مجدد قبل از ۶۰ ثانیه غیرفعال است
- [ ] رفرش صفحه → کاربر وارد می‌مانَد
- [ ] خروج → برگشت به صفحه ورود
- [ ] تغییر شماره با تأیید OTP شماره جدید
- [ ] بازیابی مدیریتی → نشست‌های قبلی قطع می‌شوند
- [ ] کاربر کلینیک A هیچ داده‌ای از کلینیک B نمی‌بیند (rls_tests.sql)

تا وقتی همه موارد بالا با پیامک واقعی سبز نشده، سیستم Production Ready
اعلام نمی‌شود.
