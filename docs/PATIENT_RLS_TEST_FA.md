# تست دسترسی‌های ماژول بیمار

فایل: `database/tests/patient_clinical_rls_tests.sql`

1. شش کاربر تست در Authentication → Users بسازید.
2. UUID ها را ابتدای فایل جای‌گذاری کنید.
3. کل فایل را در SQL Editor اجرا و پنل Logs را ببینید — این سناریوها
   باید PASS شوند:
   - جداسازی دو کلینیک (بیمار/جلسه/اندازه‌گیری کلینیک دیگر دیده نشود)
   - منشی: ویرایش اداری ✅، نوشتن جلسه/اندازه‌گیری/ارزیابی ❌
   - فیزیوتراپیست تخصیص‌یافته ✅ / تخصیص‌نیافته ❌
   - بیمار: جدول خام sessions ❌، ویو خلاصه‌های خودش ✅، اندازه‌گیری
     غیرقابل‌مشاهده ❌، قابل‌مشاهده ✅، نوشتن ❌، ارزیابی ❌
   - ثبت‌شدن ردیف‌های Audit
4. در پایان داده تست خودکار پاک می‌شود.

خطای رایج: اگر PASS 4b نگرفتید، مطمئن شوید migration 013 اجرا شده
(ویو patient_session_summaries را همان می‌سازد).

## Migration 014 — چرا لازم شد؟

بازبینی امنیتی قبل از اجرا روی Supabase واقعی این ایرادها را نشان داد و
014 همه را رفع می‌کند:

1. **write_audit باز بود:** تابع SECURITY DEFINER بود ولی EXECUTE آن از
   کاربران گرفته نشده بود → حالا فقط تریگرهای داخلی می‌توانند Audit
   بنویسند (تست ۶).
2. **دسترسی ستونی منشی:** RLS سطری است؛ منشی می‌توانست سابقه پزشکی/
   داروها/آلرژی را روی patients ویرایش کند → این ستون‌ها به جدول جدید
   `patient_clinical_background` منتقل شدند (نوشتن: ادمین/مالک/فیزیوتراپیستِ
   تخصیص‌یافته؛ منشی حتی Read ندارد — تست ۷).
3. **خواندن جدول خام sessions توسط منشی** (شامل یادداشت خصوصی درمانگر)
   → حذف شد؛ منشی فقط ویو اداری `session_admin_view` را می‌بیند (تست ۷).
4. **فیزیوتراپیستِ تخصیص‌نیافته** دیگر پرونده بالینی (session/assessment/
   measurement) را حتی نمی‌خوانَد (تست ۸).
5. **یکپارچگی داده:** clinic_id/patient_id از care_episode سمت سرور
   استخراج می‌شوند؛ session متعلق به Episode دیگر و metric کلینیک دیگر
   رد می‌شوند (تست ۹).
6. **ضد جعل نویسنده:** created_by/updated_by از auth.uid() تنظیم می‌شود؛
   UUID جعلی بی‌اثر است (تست ۹). استثنای مستند: SQL Editor/service role.
7. **شماره جلسه هم‌زمان:** شمارنده اتمی per-episode + Unique Constraint
   روی (care_episode_id, session_number)؛ شماره‌ها بعد از حذف/لغو
   بازاستفاده نمی‌شوند (تست ۱۰). پیش‌فرض قدیمی status هم اصلاح شد.
8. **اعتبارسنجی سخت‌گیرانه مقادیر:** فقط ستونِ متناظر با data_type مقدار
   می‌گیرد و واحد باید با تعریف معیار یکی باشد.
